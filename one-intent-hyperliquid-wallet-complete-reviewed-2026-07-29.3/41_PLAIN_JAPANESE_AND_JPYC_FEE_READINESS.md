# やさしい日本語・清算価格・JPYC手数料準備仕様

**版:** 2026-07-29.3  
**対象:** Android／iPhone／管理画面／オフライン画面見本  
**基本原則:** 技術用語は内部識別子として残してよいが、初心者が最初に見る画面では意味が伝わる日本語を使う。

## 1. 表示語の原則

1. 先に「何をするか」「どんな危険があるか」を日本語で示す。
2. 技術用語は、利用者が「詳しい説明」を開いた場合だけ補助的に示す。
3. 資産記号、ネットワーク固有名、正式サービス名は翻訳しない。
4. 金額、資産、送金先、ネットワーク、取引方向を音声から推測で補わない。
5. 単なる言い換えではなく、結果と危険を一文で説明する。

`config/user-facing-terms.ja.json` を表示語の機械可読な正本とし、UI、通知、エラー、音声確認画面は同じ辞書を使う。

## 2. 標準の言い換え

| 内部・業界用語 | 最初に表示する日本語 | 補足説明 |
|---|---|---|
| Perpetual / Perp | 期限なし先物取引 | 満期がなく、損失が大きいと自動決済される場合がある取引 |
| Spot | 現物取引 | 代金と引き換えに実際の資産を売買する取引 |
| Slippage | 予定価格と成立価格のずれ | 注文中に価格が動いて生じる差 |
| Bridge | 別ネットワークへの資金移動 | ネットワークをまたいで資産を移す操作 |
| Vault | 運用口座 | 元本保証ではない資産運用の預け先 |
| Gas / Gas fee | ネットワーク手数料 | 送金や交換を処理するための手数料 |
| Gas token | ネットワーク手数料を払う資産 | PolygonならPOLなど、処理に必要な資産 |
| Leverage | 取引倍率 | 元手に対してどれだけ大きく取引するか |
| Margin | 取引の担保 | 先物取引を維持するために預ける資産 |
| Liquidation price | 清算価格 | 損失が一定以上になり自動決済される目安 |
| Mark price | 清算判定に使う価格 | 清算判定に使う基準価格 |
| Reduce-only | ポジションを増やさず減らすだけ | 現在の取引量を減らす方向にしか使わない注文 |
| IOC | すぐ成立する分だけ | 今すぐ成立できない残りは取り消す方式 |
| Saga | 順番に進める複数の操作 | 途中停止時に完了済みと未完了を分ける処理 |
| Root action | 特別な権限が必要な操作 | 出金、鍵変更、権限変更など強い確認が必要な操作 |
| Agent wallet | 取引用の限定権限 | 取引だけに使える狭い権限 |
| APY | 1年あたりの利益の目安 | 将来の利益を保証しない参考値 |
| TVL | 運用中の総額 | その運用先に預けられている合計 |
| Drawdown | 過去の最大下落 | 過去の最高点から最も大きく下がった割合 |
| Lock period | 引き出せない期間 | 預けた資産を取り出せない期間 |

「ブリッジする」のような動詞だけの入力では、移動元・移動先・資産・金額が分かるまで実行下書きを確定しない。

## 3. 音声入力の聞き間違い

音声認識結果はそのまま金融操作へ変換しない。次の順に処理する。

1. 原文を保存する。
2. 文脈に基づく候補を作る。
3. 利用者向けに「読み取った内容」を日本語で表示する。
4. 金額、資産、方向、相手、ネットワーク、取引倍率を独立して検査する。
5. 一意でない場合は不足項目だけ質問し、下書きを止める。
6. 承認画面では原文ではなく、決定論コアが確定した構造化内容を表示する。

先物取引の文脈で「生産価格」と入力された場合は「清算価格」の候補にできる。ただし、清算価格という意味で読み取ったことを必ず表示する。送金先名やアドレスの聞き間違いは自動補正しない。

## 4. 先物取引の清算価格

### 4.1 注文前

注文前の確認画面には次を同時表示する。

- 清算価格の目安
- 清算判定に使う価格
- 現在価格から清算価格までの距離
- 取引倍率
- 取引の担保
- 口座方式（全体で担保を共有／取引ごとに分ける）
- データ取得時刻
- 「口座残高や他のポジションで変わる目安」である説明

見積もりは、直前に取得した口座状態、基準価格、注文サイズ、手数料、口座方式を決定論的な計算へ渡して作る。AIモデルへ計算させない。

### 4.2 成立後

約定後はHyperliquidの口座状態に含まれる `liquidationPx` を取得し、見積もり表示を実際の清算価格へ更新する。約定平均価格、現在の清算判定価格、清算までの距離、取得時刻も更新する。

### 4.3 情報が不完全な場合

次の場合は、清算価格を「0」「安全」「計算不能ではない値」として埋めない。

- 口座状態が古い
- `liquidationPx` が未提供
- 対象ポジションを特定できない
- 口座全体の担保方式により単一価格だけでは誤解を生む
- 基準価格の取得元が一致しない

この場合は「清算価格を正確に確認できないため実行を止めました」と表示し、口座全体の担保使用率、利用可能残高、再取得ボタン、具体的な手動確認手順を示す。

## 5. JPYCしかない場合のネットワーク手数料準備

### 5.1 判定状態

| 状態 | 動作 |
|---|---|
| 手数料用残高が十分 | 交換せず、そのまま送金下書きへ進む |
| 少ないが交換処理を開始できる | JPYCから目標残高までの必要最小限だけ交換する |
| 残高が0で通常の交換も開始できない | 監査済みの代理支払い／立替機能が利用できる場合だけ使う |
| 代理支払いが使えない | 外部から必要額を受け取る具体的手順を表示する |
| 正式資産、経路、価格、流動性を検証できない | 実行せず手動案内へ切り替える |

残高0では、通常のオンチェーン交換にも手数料が必要である。そのため「JPYCを少し交換すれば必ず解決する」と表示してはならない。

### 5.2 自動準備の上限

初回設定で明示的に許可された場合だけ、次の固定条件を使える。

- 対象ネットワークの許可一覧
- JPYCの正式コントラクト
- 交換先となる手数料用資産
- 利用できる交換経路または代理支払い事業者の許可一覧
- 1回あたりのJPYC上限
- 1か月あたりのJPYC上限
- 目標残高（例: 通常送金3回分）
- 予定価格と成立価格のずれの上限
- 見積もり有効期限
- 権限の期限
- いつでも停止できる設定

AIは「今月は多めに補充した方がよい」などの裁量判断をしない。残高、見積もり、上限、使用履歴を決定論ポリシーで評価する。

### 5.3 代理支払い

代理支払いまたは初回立替は、次を満たす場合だけ使う。

- 事業者とコントラクトが許可一覧に固定されている
- 監査、資金源、悪用対策、停止手段が確認済み
- 対象操作と最大費用が署名対象へ含まれる
- 利用者にJPYCで差し引く最大額を事前表示する
- 二重徴収、再送、見積もり期限切れを防ぐ識別子がある
- 月間上限と初回利用回数をサーバー側で強制する
- 失敗時にJPYC送金だけが行われない状態を明示する

機械可読な下書きは `schemas/fee-readiness-plan.schema.json`、例は `examples/fee-readiness-jpyc-only.json` を使う。

## 6. JPYC発行の連携範囲

ウォレットはJPYC EXへのログイン・アカウント連携、発行／償還画面への導線、ウォレットアドレス登録補助、手続き状態の連携を実装対象にする。本人確認、追加認証、審査、申込みの最終受付、発行／償還の確定をウォレットやAIが代行する設計にはしない。

受け取り後は、ネットワーク、正式コントラクト、残高増加、取引識別子、確認数を検証してから「受け取り完了」と表示する。

## 7. 受入条件

- 最初の画面に `Perp`、`Spot`、`Bridge`、`Vault`、`Slippage` を単独の主要ラベルとして出さない。
- 先物確認画面に清算価格または取得不能の明示がある。
- JPYCだけ・手数料用残高0のケースで、通常交換を無条件に提案しない。
- 十分な残高があるケースでは不要な交換をしない。
- 自動化不能時に、押すボタン名、画面名、安全確認、期待結果を表示する。
- `python tools/check_plain_japanese.py` が通る。
- 6端末proxy×12画面×2文字モード×2テーマ＝288条件の画面検査が通る。
