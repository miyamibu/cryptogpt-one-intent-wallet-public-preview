# 自動でできない場合の操作案内仕様

**版:** 2026-07-29.3  
**目的:** AI、API、代理支払い、外部ウォレット、ネットワーク処理のどこかで止まっても、利用者が「次にどの画面で何を押すか」を理解できる状態にする。

## 1. 必須表示

自動処理ができない場合、エラー番号だけを出して終えてはならない。次を同じ画面へ表示する。

1. できなかったこと
2. 止めた理由
3. 資産が現在どこにあるか
4. 完了済みの操作
5. 未実行の操作
6. 現在開いている画面名
7. 次に押すボタンの正確な表示名
8. 1手順ごとの期待結果
9. アドレス・ネットワーク・金額の安全確認
10. 再試行ボタン
11. 問い合わせ用の識別番号

「設定を確認してください」「別の方法を試してください」「ウォレットで操作してください」のような曖昧な案内は禁止する。

機械可読形式は `schemas/manual-fallback.schema.json`、例は `examples/manual-fallback-zero-gas.json` とする。

## 2. 手順データの作り方

手順は生成AIだけで作らない。対応アプリ版、OS、画面遷移、機能gateに紐づいた署名済みの手順カタログをbackendで管理する。AIは読み上げや言い換えだけを行い、ボタン名、ネットワーク、アドレス、金額、URLを変更しない。

各手順には次を含める。

- `reasonCode`
- 対応アプリ版の範囲
- OSと画面名
- 正確な操作部品名
- 期待結果
- 進んではいけない条件
- 有効期限
- 再試行先
- support code

アプリ更新でボタン名や位置が変わった場合は、旧手順を失効させる。

## 3. 代表手順

### 3.1 PolygonでJPYCしかなく、POLが0

1. ホーム画面下の「資産」を押す。
2. 資産一覧右上の「受け取る」を押す。
3. 「Polygon」を選ぶ。
4. 表示された受取アドレスをコピーし、先頭・末尾を確認する。
5. 別のウォレットまたは取引所で、送金先ネットワークをPolygon、資産をPOLにする。
6. アプリが対象操作に結び付けて再計算した「推奨送金量」と「上限」を確認し、その範囲内のPOLを送る。静的な画面見本では固定量を表示しない。見積もりID、対象操作、有効期限、推奨量、上限のいずれかを取得できない場合は送らない。
7. このアプリへ戻り「残高を更新」を押す。
8. 手数料用残高が反映されてから、元のJPYC送金を再確認する。

Ethereum、Arbitrumなど別ネットワークから同じ見た目のアドレスへ送るよう誘導してはならない。

### 3.2 JPYC発行

1. ウォレットの「JPYCを受け取る」を押す。
2. 金額、受取ネットワーク、受取アドレスを確認する。
3. 「JPYC EXで発行手続きを始める」を押す。
4. JPYC EX側でログイン、本人確認、追加認証、金額確認、最終申込みを行う。
5. 完了後にウォレットへ戻る。
6. 「入金を確認」を押す。
7. 正式コントラクトと受取ネットワークが一致した入金だけを完了表示する。

ウォレットはJPYC EX上の最終申込みを代行したと表示しない。

### 3.3 Hyperliquidの取引用限定権限を設定できない

1. アプリの「設定」を押す。
2. 「取引の権限」を押す。
3. 「取引用の限定権限を追加」を押す。
4. 有効期限、1回・1日上限、取引倍率、対象市場を確認する。
5. Existing Wallet Modeでは「外部ウォレットで確認」を押す。
6. 外部ウォレット上の公式ドメイン、権限内容、有効期限を確認する。
7. 完了後にアプリへ戻り「権限を再確認」を押す。

権限追加画面が公式仕様と一致しない場合は進めない。

### 3.4 清算価格を取得できない

1. 先物確認画面の「口座情報を更新」を押す。
2. 取得時刻が更新されたか確認する。
3. 「清算判定に使う価格」と口座方式を確認する。
4. それでも表示できない場合は、取引を実行しない。
5. 「Hyperliquidで確認する」を押し、読み取り専用の公式画面へ移る。
6. 同じ口座・銘柄・方向・取引量であることを確認する。

単一の清算価格を提供できない口座方式では、担保使用率と説明を表示し、値を捏造しない。

### 3.5 ネットワークが違う

1. エラー画面の「受取ネットワークを見る」を押す。
2. 送る側と受ける側のネットワーク名を並べて確認する。
3. 同じネットワークでない場合は送金を中止する。
4. 「別ネットワークへの資金移動」を選び、移動元・移動先・資産・金額を新しく確認する。

既に送信済みの取引を「取り消せる」と誤表示しない。

### 3.6 外部ウォレットの確認待ち

1. 状態画面で「外部ウォレットを開く」を押す。
2. 外部ウォレットで待機中の要求が1件であることを確認する。
3. 金額、資産、送金先、ネットワーク、権限、有効期限を照合する。
4. 一致しない場合は拒否する。
5. 完了後に元のアプリへ戻り「状態を更新」を押す。
6. broadcast識別子を受信するまで「完了」と表示しない。

## 4. 部分成功

複数操作の途中で止まった場合、最初から繰り返さない。各工程を次の状態で表示する。

- 完了
- 受付済み・到着待ち
- 未実行
- 失敗
- 手動確認待ち
- 取消済み

資産の現在位置、再試行する工程、再試行しない工程を明示する。idempotency keyと外部取引識別子を照合し、二重送金を防ぐ。

## 5. アクセシビリティ

- 手順番号だけで状態を伝えず、文章でも示す。
- 色だけで成功・警告・失敗を区別しない。
- VoiceOver／TalkBackで画面名、ボタン名、安全確認を順番に読み上げる。
- 文字を大きくしてもボタン、アドレス、注意文を省略しない。
- コピーしたアドレスの確認方法を示す。
- 問い合わせ用識別番号は読み上げ・コピー可能にする。

## 6. 受入条件

- 主要な失敗理由すべてに手順カタログがある。
- 実際のアプリ版と一致しない手順は表示されない。
- 最低1つの手動復旧フローをiOS／Android実機で端から端まで検証する。
- 手順中のボタン名をUI test IDと結び、画面変更時にテストを失敗させる。
- 利用者が手順を終えた後、元の処理を二重実行せず再評価する。
