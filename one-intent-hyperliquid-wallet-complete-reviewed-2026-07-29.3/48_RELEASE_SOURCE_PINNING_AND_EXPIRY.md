# 外部情報の固定・有効期限・失効

**版:** 2026-07-29.3

## 1. 目的

暗号資産、API、規約、Store条件、法令、提供者能力は変わる。文書に一度書いた値を永続的な真実として使わない。本番の書き込みは、最新版を確認した署名済み情報へ束縛する。

## 2. 情報区分

| 区分 | 例 | 期限切れ時 |
|---|---|---|
| 資産登録 | JPYCアドレス、桁数、ネットワーク | 対象資産の全書き込み停止 |
| Hyperliquid仕様 | 署名、注文、出金、清算情報 | 対象機能停止 |
| 手数料経路 | paymaster、relayer、費用、精算先 | 自動手数料準備停止 |
| JPYC EX連携 | handoff、callback、資格情報 | 発行／償還導線停止 |
| OpenAI境界 | ChatGPT App/APIの許容範囲 | ChatGPT側機能を読み取り専用へ縮退 |
| Store／法務 | 提出主体、申告、地域 | 公開配布停止 |

具体的な最大経過時間と競合時処理は`config/release-source-policy.yaml`に置く。

## 3. 書き込み時の条件

書き込み前に、少なくとも次を同じExecution Capsuleへ固定する。

- registry IDとentry hash
- protocol adapter version
- capability ID
- quote IDとexpiry
- policy version
- source-state timestamp

期限切れデータは「注意を表示して続行」ではなく、原則として再取得または停止とする。

## 4. 二つの情報源が食い違う場合

優先順位だけで勝手に片方を採用しない。競合状態を記録し、対象書き込みを止める。管理者は、一次情報、取得時刻、内容ハッシュ、判断者、根拠、失効期限を残して解決する。

## 5. 変更監視

- 定期取得
- 内容ハッシュ差分
- HTTP状態と証明書異常
- Schema互換性
- protocol/testnet smoke test
- 公式告知の人手確認
- 変更を受けた機能の自動gate縮退

監視が止まった場合も「変更なし」ではなく「確認不能」と扱う。

## 6. 本ZIPの限界

収録された外部情報は、設計判断の根拠を示す資料であり、本番実行時のライブ固定値ではない。本番登録情報を作成する作業はCodexプロンプトの外部証拠要件へ残している。
